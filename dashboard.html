Case study

Data Issue Detection Dashboard

An internal tool I designed from start to finish to cut bug investigation time from hours to seconds.

The dashboard lets anyone in the company check whether a problem is a data issue, and raise a ticket with the right team, without waiting for the analytics team to investigate first.

30 → 4internal data issue tickets per week, on average
Hours → secondsto investigate a suspected data bug
50%+faster to raise and resolve issues

The problem

When something looked wrong, the analytics team had to investigate first to find out whether it was a data issue. That took hours and added an extra step before the right team heard about it.

The result

Other teams can now check for themselves, see whether it is a data issue, and raise the ticket with the correct team. Removing that extra step sped up raising and resolving issues by at least 50%.

How I built it

  1. Found the gaps. I identified where gaps, abnormalities and duplications appear in the data.
  2. Wrote the Snowflake queries. I built complex SQL that brings the data through in a form that is easy to present, so gaps, abnormalities and duplications show up as clear spikes and drops on the graphs.
  3. Scaled it with Python. I used Python to run the SQL script across every datamart, so one dashboard covers all client information.
  4. Connected the BI tool to Snowflake. The tool connects directly to Snowflake, and the only input a user needs is the schema name and the date to investigate.
  5. Added an AI agent. To cut investigation time further, I connected an agent to the visuals. It uses detailed orchestration to pick out spikes and drops, tells the user to check them against the source of truth (agents can be wrong), and guides them through creating a ticket.
